# 家計簿アプリ 要件・設計

> このドキュメントは実装しながら更新していく。変更したら「変更履歴」に追記する。

## 1. コンセプト

個人用のシンプルな家計簿アプリ。月単位で収支を確認し、その実績をもとに翌月の予算を決める運用を軸にする。

- 想定端末: **PC（ブラウザ）**。レイアウトはデスクトップ幅を前提とする（左サイドバー＋メイン領域）
- 月の区切り: **カレンダー月**（1日〜月末）

## 2. 技術構成

| 項目 | 採用 | 備考 |
| --- | --- | --- |
| ビルド | Vite + TypeScript | |
| UI | React 19 | |
| ルーティング | React Router（HashRouter） | 静的ホスティングでサーバー設定不要にするため |
| 永続化 | IndexedDB + Dexie.js | `dexie-react-hooks` の `useLiveQuery` で画面へ自動反映 |
| グラフ | Recharts | React コンポーネントとして書けるため Chart.js より採用 |
| スタイル | Tailwind CSS v4 | |
| テスト | Vitest + fake-indexeddb + Testing Library | 集計・期間計算・リポジトリ層に加え、画面の主要操作もテスト |
| ホスティング | 静的ホスティング（GitHub Pages / Cloudflare Pages 等） | `base: './'` でサブパス配信にも対応 |

バックエンドは持たない。データは端末内（ブラウザの IndexedDB）で完結させ、将来のクラウド同期に備えた設計にしておく（§6）。

## 3. データモデル

### 共通メタデータ（全エンティティ）

| フィールド | 型 | 説明 |
| --- | --- | --- |
| id | string (UUID) | 端末間で衝突しない ID。自動採番は使わない |
| createdAt | ISO 8601 日時 | 作成日時 |
| updatedAt | ISO 8601 日時 | 最終更新日時（同期時の新旧判定に使う） |
| deletedAt | ISO 8601 日時 \| null | 論理削除。物理削除はしない |

### Transaction（取引）

| フィールド | 型 | 説明 |
| --- | --- | --- |
| date | "YYYY-MM-DD" | 取引日（ローカル日付） |
| amount | 整数（円） | 常に正。収支の向きは type で表す |
| type | "income" \| "expense" | 収入 / 支出 |
| categoryId | string | Category.id |
| memo | string | 任意 |

### Category（カテゴリ）

| フィールド | 型 | 説明 |
| --- | --- | --- |
| name | string | |
| type | "income" \| "expense" | 入力フォームで種別に合うカテゴリだけ出すため。作成後は変更不可 |
| color | "#RRGGBB" | グラフ用。既定は色覚の違いがあっても隣り合って見分けられることを検証した8色（`src/db/defaults.ts`）＋「その他」の灰色 |
| order | number | 表示順 |
| archived | boolean | アーカイブ済みは新規入力の選択肢に出さない。過去データ表示には使う |

カテゴリは削除せずアーカイブする（取引が残っているカテゴリを消すと履歴が壊れるため）。
初回起動時に既定カテゴリを作成する（`src/db/defaults.ts`）。

### Budget（予算）

| フィールド | 型 | 説明 |
| --- | --- | --- |
| yearMonth | "YYYY-MM" | 対象月 |
| categoryId | string | 支出カテゴリの id |
| amount | 整数（円） | 0 以上 |

- `(yearMonth, categoryId)` で一意。月ごとに独立
- 予算は支出カテゴリのみ（収入の予算は MVP では扱わない）
- 行がない＝未設定。「0 円」と「未設定」は区別する

### RecurringRule（固定費）

| フィールド | 型 | 説明 |
| --- | --- | --- |
| name | string | 名前（確定した取引のメモになる） |
| type | "income" \| "expense" | 収入 / 支出 |
| categoryId | string | Category.id |
| amount | 整数（円） | 目安の金額（確定時に変更できる） |
| dayOfMonth | 1〜31 | 毎月の日。その月にない日は月末 |
| startMonth / endMonth | "YYYY-MM" / null | 期間。endMonth が null なら終わりなし |
| skippedMonths | "YYYY-MM"[] | 「この月はなし」にした月 |

固定費から確定した取引は Transaction に `recurringId`（固定費の id）と `recurringMonth`（何月分か）を持つ。

### Settings（アプリ設定）

| フィールド | 既定値 | 説明 |
| --- | --- | --- |
| monthStartDay | 1 | 月の開始日。現在はカレンダー月（1）で運用 |
| carryOverBudget | true | 翌月予算が未設定なら前月予算を初期値として提示する |
| lastBackupAt | null | 最後にバックアップをエクスポートした日時 |

## 4. 画面構成

PC 向け。左サイドバーで画面を切り替える（今月の記録 / 月次サマリー / 推移 / 予算設定 / 履歴 / 固定費 / 設定）。

### 4.1 今月の記録（`#/record`）
- 収支入力フォーム: 日付（既定は今日）、種別、金額、カテゴリ（種別に応じて絞り込み）、メモ
  - 日付は「2026/9/25（金）」と曜日つきで表示。クリックでカレンダー、‹ › ボタン（または ← →）で1日ずつ動かせる
  - 連続入力しやすいよう、保存後は金額・メモだけクリアし、日付・種別・カテゴリは保持する
  - 金額は「1,200」「１２００」なども受け付ける
  - Enter で保存。今月以外の日付で保存した場合は「◯月の取引として保存しました」と案内する
- 今月の取引一覧（新しい順）。行にマウスを乗せると編集・削除ボタンを表示。編集は行内で行い、Esc でキャンセル。削除は確認ダイアログを出す
- 今月の収入・支出・収支の合計

### 4.2 月次サマリー（`#/summary/:yearMonth`）
- 収入・支出・収支の合計
- 支出の内訳（ドーナツ型の円グラフ）: 金額の大きい順に上位5カテゴリ＋「その他（まとめ）」。中央に支出合計、横に金額と割合の表。マウスを乗せたカテゴリを中央に表示
- カテゴリ別の支出と予算: カテゴリごとに実績を棒、予算を縦線で同じ目盛りに並べる（棒グラフと予算比較を1つにまとめた）。「残り ¥X」「▲ ¥X 超過」「予算未設定」を文字でも表示
- 前月・翌月・今月への切り替え（今月より先には進めない）

### 4.3 予算設定（`#/budget/:yearMonth`、既定は来月）
- 月を切り替えて、来月だけでなく今月や過去の月の予算も設定・修正できる（来月より先には進めない）
- カテゴリごとに予算額を入力。入力欄から離れるか Enter で自動保存し、Enter で次のカテゴリへ移る。空欄で「未設定」に戻る
- 参考値として横に表示（ラベルは「9月の実績（途中）」のように月名で表示）
  - 前月の予算
  - 前月の実績（前月が今月なら「途中」と表示。予算超過なら ▲）
  - 前々月の実績（来月の予算を決めるときは、先月の確定実績）
  - 直近3か月平均（締まった月のみ。記録のない月は平均に含めない）
- 参考値をクリックすると、その金額が予算に入る
- 「未入力のカテゴリに前月の予算をコピー」ボタン（入力済みのカテゴリは上書きしない）
- carryOverBudget が有効なら、未入力の欄に前月の予算を薄く表示する（保存はされない）
- 合計行と「前月の収入 − 予算合計」の参考表示

### 4.4 履歴（`#/history/:yearMonth`、既定は前月）
- 前月・翌月ボタンと年月の直接選択で月を切り替える（今月より先は表示しない）
- 選択月の入力フォーム・合計・取引一覧（今月の記録画面と同じ部品）。過去の月の取引も追加・編集・削除できる
  - 入力フォームの日付の初期値は、その月の最終日（今月なら今日）
- 選択月の月次サマリー（グラフ）へのリンク

### 4.5 推移（`#/trends`）
- 期間: 「直近12か月」（既定）と「年ごと」（1〜12月、年を選択）を切り替え
- カテゴリ×月の表（先頭に支出合計の行）
  - 各セルの色で、そのカテゴリの**期間の平均**と比べた多さ・少なさを表す（青 = 平均より少ない、赤 = 多い、±10%以内は色なし。10〜30% と 30%以上の2段階）
  - 平均は、締まった（今月より前の）記録のある月だけで計算。今月は「途中」として薄く表示し、平均・色分けに含めない
  - 右端に平均と「最近の傾向」（最近3か月の平均が期間の平均より 10%以上多い ▲ / 少ない ▼ / 横ばい）。締まった月が4か月未満なら表示しない
- 行をクリックすると、そのカテゴリ（または支出合計）の折れ線グラフ（実績・予算・平均）を表示

### 4.6 固定費（`#/recurring`）
- 家賃・サブスク・給与など毎月決まった取引を登録（名前・種別・カテゴリ・目安の金額・毎月の日・開始月・終了月）
- 毎月、自動では記帳せず「確認待ち」に並べる（開始月から今月までで、確定もスキップもしていない月）
  - 確認待ちは「今月の記録」画面の上部と固定費画面に表示。サイドバーの「固定費」に件数を表示
  - 金額を直して「確定」→ 取引として記録（一覧に「固定」の印）。「この月はなし」→ その月は記帳しない
  - 「すべて目安の金額で確定」ボタン
  - 確定した取引を後で削除しても、再び確認待ちにはならない
- 繰り返しは毎月のみ（年1回などは対象外）
- 編集・削除（削除しても確定済みの取引は残る）

### 4.7 設定（`#/settings`）
- バックアップ: JSON エクスポート / インポート（全置き換え）、最終バックアップ日時
- データの保存状態（ブラウザに保護されているか）と保護のリクエスト
- カテゴリ管理（支出・収入別）
  - 名前の変更（直接編集、Enter で保存）。同じ種別で同じ名前は不可
  - 色の変更（検証済みの8色＋灰色から選択。「その他の色」で自由に指定も可）
  - 並べ替え（↑↓）。入力フォームやグラフの並び順に反映
  - 追加（色は同じ種別でまだ使っていない色を自動で提案）
  - アーカイブと戻す（アーカイブしても過去の取引・集計には残る）

## 5. データ保全

- IndexedDB はブラウザのデータ削除などで消える可能性がある
- 起動時に `navigator.storage.persist()` で永続化を要求する
- JSON エクスポート / インポートを提供する（論理削除済みの行も含めて出力）
- 設定画面に「データの保存状態」（ブラウザに保護されているか）と最終バックアップ日時を表示する
- サイドバー下部にバックアップ状況を常に表示し、未実施または30日を超えたら注意表示にする
- バックアップには `schemaVersion` を持たせ、古い形式は読み込み時に変換する

## 6. 変更しやすさのための設計方針

| 将来ありうる変更 | 備え |
| --- | --- |
| 月の区切りを給料日基準にする | 月の範囲計算を `src/domain/period.ts` に集約し、`monthStartDay` を参照する。値の変更だけで切り替え可能 |
| クラウド同期 | UUID・updatedAt・論理削除を最初から持つ。UI は `src/db/repository.ts` 経由でしかデータに触れない |
| データ構造の変更 | Dexie の `version(n)` を追加してマイグレーション。バックアップも `schemaVersion` で変換 |
| 画面・グラフの変更 | 集計は `src/domain/aggregate.ts` の純粋関数に分離し、UI から独立させる |
| 項目追加（支払方法・タグなど） | Transaction にフィールドを追加し DB バージョンを上げる。既存データは upgrade で既定値を補う |

### レイヤー構成

```
pages / components  … 画面（React）
      ↓
hooks/useData.ts    … DB をリアクティブに購読
      ↓
db/repository.ts    … データアクセス（検証・論理削除・メタデータ付与）
      ↓
db/db.ts            … Dexie スキーマ
domain/*            … 型・期間計算・金額・集計（純粋関数、どこからでも使える）
```
